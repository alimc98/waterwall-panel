# سیستم نظارت بر سلامت تونل‌ها (watchdog)

واتروال هیچ API آماری ندارد، پس «آیا این تونل دیتا رد می‌کند؟» باید از بیرون سنجیده شود. ایجنت روی هر سرور پورت‌های مهم سمت خودش را پروب می‌کند و پنل از گزارش‌های آن یک قضاوت به ازای هر تونل می‌سازد.

## پروب‌ها چگونه انتخاب می‌شوند
پنل لیست پروب‌ها را از خود کانفیگ تولیدی می‌گیرد، نه از نام گزینه‌ها:

- **سمت ایران (و رله):** هر `TcpListener` بدون `whitelist` ورودی کاربران است → پروب `users` روی همان پورت از loopback.
- **سمت خارج:** `TcpConnector`های سرِ زنجیره (بدون `next`) مقصد نهایی‌اند:
  - آدرس برابر سرور ایران → پروب `link` (لینک معکوس: همان چیزی که `ReverseClient` نگه می‌دارد).
  - غیر آن → پروب `exit` (سرویس محلی یا مقصد خروجی).
- **خروجی کمکی (helper):** خروجی اصلی سرویس محلی را دارد، کمکی نه؛ پس کمکی فقط `link` پروب می‌گیرد (پروب `exit` به localhost آن باکس بی‌معنی است).

## قضاوت‌ها
| state | معنی |
| --- | --- |
| `ok` | سرویس فعال و همهٔ پروب‌ها پاسخ می‌دهند |
| `service-down` | سرویس واتروال روی یکی از سرورها خاموش است |
| `entry-down` | ورودی کاربران روی ایران پاسخ نمی‌دهد |
| `exit-down` | سرویس محلی/مقصد روی **همهٔ** خروجی‌ها قطع است |
| `link-down` | خروجی‌ها به پورت معکوس ایران نمی‌رسند |
| `degraded` | بخشی از خروجی‌ها یا لینک‌ها قطع است |
| `unknown` | هنوز گزارشی از ایجنت نشده (ایجنت قدیمی یا تازه نصب) |

## رفتار خودکار
- پنل هر `WW_WATCHDOG_MS` (پیش‌فرض ۶۰۰۰۰) قضاوت را تازه می‌کند، رویداد می‌نوید و رابط را از طریق SSE به‌روز می‌کند.
- با `WW_WATCHDOG_RESTART=1` پنل سرویس واتروالِ سمت شکست‌خورده را ری‌استارت می‌کند (فقط وقتی سرویس فعال است ولی پروب قطع است — یعنی پروسه واتروال گیر کرده). برای هر تونل+سرور کول‌داون ۱۰ دقیقه (`WW_WATCHDOG_COOLDOWN_MS`) است.
- «خروجی قطع» با سرویس فعال **ری‌استارت نمی‌شود**: آن یعنی سرویس محلی پشت تونل (مثلاً xray) روی `finalPort` نیست و ری‌استارت واتروال درستش نمی‌کند. رویداد پورت را نام می‌برد تا کار عملی باشد.
- سرور بدون دسترسی SSH (فقط ایجنت) توسط خود ایجنت پوشش داده می‌شود: ایجنت در هر چرخه، سرویس غیرفعال را بالا می‌آورد.

## تنظیم
```bash
# /etc/waterwall-panel.env
WW_WATCHDOG=1            # خاموش کردن: 0 (گزارش SSE هم متوقف نمی‌شود، فقط تیک نمی‌زند)
WW_WATCHDOG_MS=60000
WW_WATCHDOG_RESTART=1    # ری‌استارت خودکار سمت شکست‌خورده
WW_WATCHDOG_COOLDOWN_MS=600000
```

## API
- `GET /api/tunnels` — هر تونل حالت `health` را با خودش دارد.
- `GET /api/tunnels/:id` — `health` در پاسخ.
- `GET|POST /api/tunnels/:id/health` و `/healthcheck` — قضاوت لحظه‌ای (بر پایهٔ آخرین گزارش ایجنت، حداکثر ۱۵ ثانیه تأخیر).
- `GET /api/watchdog` — وضعیت کل: تنظیمات، آخرین تیک، قضاوت همهٔ تونل‌ها.

## محدودیت‌ها
- پروب یک TCP connect ساده است: شنونده بالا باشد = سالم. این یعنی «لینک برقرار است»، نه «دیتا رد می‌شود» — برای آن باید ترافیک واقعی بدوید. با این حال ترکیب «سرویس فعال + لینک برقرار + خروجی پاسخ می‌دهد» تقریباً همهٔ حالت‌های قطعی را می‌گیرد.
- ایجنت باید به نسخهٔ ۱.۲.۰ (یا جدیدتر) بروز باشد تا `checks` را گزارش کند؛ با ایجنت قدیمی قضاوت `unknown` می‌ماند.
